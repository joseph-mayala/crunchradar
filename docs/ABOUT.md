# GitHub About, README About and repo branding

Copy written to be specific, plain, and checkable. It states what the project is, shows one piece of evidence, and says what it is not. Every claim below is true of this repository today.

## 1. GitHub "About" box (Settings: the gear next to About, max 350 characters)

**Description (recommended, 263 characters):**

> CrunchRadar reads a cohort's deadlines and briefs, adds up the real hours per week, and proposes deadline moves for a person to approve. Gemini agent, rules engine and MCP tools, tested end to end on a sample cohort. APU Cloud Innovation Hackathon 2026.

Shorter alternative (190 characters):

> Spots crunch weeks before students hit them and proposes deadline moves a person approves. Gemini agent, rules engine, MCP tools. Sample-cohort prototype for the APU Cloud Innovation Hackathon 2026.

**Website:** `https://joseph-mayala.github.io/crunchradar/`

**Topics:** `gemini` `mcp` `model-context-protocol` `workflow-automation` `human-in-the-loop` `education` `fastapi` `react` `typescript` `hackathon`

## 4. README "About" (already added near the top of README.md)

Why the wording is built this way: it opens with the problem in the reader's own terms (nobody sees the whole cohort's week), gives the mechanism in one sentence, puts the safeguard (a person decides) before the cleverness, and says plainly what is sample and what is not. Confidence comes from specifics a judge can check (tests, numbers, the demo), not from adjectives.
